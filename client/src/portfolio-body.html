9 Core Engineering Components

1. Data Management Engine

Flexible table-oriented schema supporting configurable fields, multi-type values, unique constraints, duplicate detection, and high-performance bulk operations.

2. Authentication & RBAC

Role-based architecture (Owner, Admin, Assistant, Operator) strictly governing permissions for view, create, edit, verify, approve, download, and user administration.

3. Workflow Management

Explicit lifecycle transitions making it possible to track progress across large datasets with complete administrative visibility.

4. Audit Logging Layer

Records who performed an action, what operation occurred, affected record, timestamp, and field-level diffs for full organizational compliance.

5. Import & Export Engine

Imports CSV, XLSX, and ZIP photo datasets with automatic schema validation; exports XLSX, CSV, print-ready PDF, and DOCX outputs.

6. Photo Pipeline

Dedicated processing for student & relationship photographs, missing photo indicators, and auto-cropping to prevent misprinted physical cards.

7. Background Processing

Celery + Redis workers offload heavy image manipulation, PDF compilation, and large imports from the synchronous HTTP request thread.

8. REST API Architecture

Django REST Framework API-first backend providing centralized endpoints for auth, cards, workflows, and batch operations across all clients.

9. Cross-Platform Ecosystem

Shared backend logic serving React Web, Electron Desktop, and React Native Android clients with identical business rules.

5 Real Engineering Challenges Overcome

1. Large Dataset Operations

Users needed to search, filter, sort, verify, and approve 136K+ card records without UI lag. Solved via database indexing, query optimization, and bulk SQL updates.

2. Multi-User Operations & RBAC

Prevented unauthorized operations across organizations with an explicit permission matrix enforced at both API serializers and service layers.

3. Long-Running Operations

Moving multi-thousand record exports and photo calibrations into Celery background workers decoupled user actions from HTTP response timeouts.

4. Source Data Quality & Deduplication

Implemented checksum duplicate detection and pre-generation validation checks to eliminate missing photographs and corrupt rows before printing.

5. Real Production Reliability

Refined error handling, graceful fallback for malformed spreadsheets, and seamless rolling updates on production Linux servers.

Key Architectural Decisions

Why Django & DRF?

Provided a mature ORM, built-in security protections, robust admin interface, and standardized REST API endpoints for multiple client platforms.

Why PostgreSQL?

Strict ACID guarantees, relational integrity for multi-tenant data, fast B-tree indexing on search fields, and battle-tested production reliability.

Why Redis & Celery?

Eliminated web request blocking during heavy image finishing, PDF compilation, and bulk imports by queuing tasks in background workers.

Why API-First Architecture?

Allowed React Web, Electron Desktop, and Android to share identical business rules, validation schemas, and database transactions.

Frequently Asked Questions

Below is a list of frequently asked questions about my development work, technical expertise, and collaboration process.

What is your primary tech stack? +

My primary stack is Python / Django on the backend with React on the frontend, PostgreSQL as the main database, and Redis + Celery for background processing and caching. For deployment I use Nginx, Gunicorn, and Linux-based servers. I also work with Electron for desktop clients, and REST APIs for all integrations.

Tell me about CardFlow — what did you build exactly? +

CardFlow is a production SaaS platform I designed and built from scratch for Adarsh ID Cards. It handles the complete ID card pipeline: data ingestion, verification workflows, approval stages, photo processing, card generation, and download management — for schools and organizations. It's currently serving 1,000+ real users across multiple organizations and processes tens of thousands of card records. The architecture includes a Django REST API, React web client, Electron desktop client, RBAC, Celery background workers, and a PostgreSQL database.

Are you open to freelance or new opportunities? +

Yes, I'm open to the right opportunities — particularly projects involving production-grade SaaS, AI-integrated systems, backend architecture, or full-stack engineering. I'm also available for technical consulting and freelance work. Reach out via the contact form and let's talk about what you're building.

How do you approach system design and architecture? +

I start by understanding the real business requirements and data lifecycle, not just the feature list. I design for the workflows first, then choose the right architecture to support them. I separate concerns clearly — API layer, business logic, data layer, background processing — and avoid over-engineering early. My CardFlow architecture is a good example: multi-client (web + desktop) against a single API backend with clear workflow state machines.

What kind of AI work have you done? +

I've integrated LLMs, RAG pipelines, and AI agents into production and prototype systems. VidyaMaxx, my school management platform, includes AI-powered features for academic workflows. I also built TaskFlixx — an AI-driven task management tool — and PrepSarthi, an AI-assisted exam preparation platform. My AI work focuses on practical integrations that add real business value, not just demo-level experiments.

Can you work on an existing codebase or take over a project? +

Absolutely. I've taken codebases from scratch to production, and I'm equally comfortable onboarding into existing systems. My approach is to understand the current architecture before changing anything, identify pain points systematically, and refactor incrementally with minimal disruption to ongoing operations.

How do you handle deployment and production operations? +

I manage the full deployment stack — Nginx as a reverse proxy, Gunicorn for WSGI serving, Celery workers with Redis, PostgreSQL tuning, and Linux server management. I've operated CardFlow in production serving real users, so I understand what it takes to keep systems reliable, handle database migrations safely, and manage background job failures gracefully.

Are your projects open source? +

Some are, some aren't. CardFlow and EazeTrip are private since they serve real clients in production. VidyaMaxx is currently in pilot testing. TaskFlixx and PrepSarthi are open source — you can find them on my GitHub. I believe in contributing to the open-source ecosystem while also understanding when code is proprietary business logic.
